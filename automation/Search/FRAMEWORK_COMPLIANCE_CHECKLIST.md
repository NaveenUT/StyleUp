# Framework Compliance Checklist

Each line below was actually verified against the repository (grep/tsc), not assumed.

- [x] Every new page class extends `BasePage` — `LoginPage`, `HomePage`, `SearchResultsPage`, `CartPage` all declared `extends BasePage`.
- [x] Every locator lives in a page class, none in a spec file — audited via `grep -rn "page\.locator(\|page\.getByRole(\|page\.getByText("` across `tests/`; every hit found during development was moved into a page-class method/getter (e.g. `SearchResultsPage.footerCell()`, `.filterSpanFor()`, `HomePage.footerTable`, `BasePage.body`). Final grep returns zero matches.
- [x] Every page class has a matching fixture in `fixtures/customFixtures.ts` — `loginPage`, `homePage`, `searchResultsPage`, `cartPage`, each constructing its class and calling `setup()`.
- [x] No spec file imports from `'@playwright/test'` — final grep returns exactly one hit, `import type { APIRequestContext } from '@playwright/test'` in `InterfaceContract.spec.ts`, a type-only import (no runtime `test`/`expect`), needed for a helper function's parameter type. Every spec file's `test`/`expect` comes from `fixtures/customFixtures.ts`.
- [x] No spec file contains `new <Page>Page(` — the only two occurrences (`Concurrency.spec.ts`, for TC-080/081's second tab/context) were moved to a page-class static factory, `SearchResultsPage.forPage()`; final grep for `new (LoginPage|HomePage|SearchResultsPage|CartPage)\(` across `tests/` returns zero matches.
- [x] No hardcoded URL, username, password, or timeout outside `.env`/`utils/config.ts` — audited via grep for `localhost:5501` and for the seeded test credentials outside `test-data/testData.ts`. The only two `localhost:5501` occurrences in actual code (not file-header comments) are `utils/config.ts`'s own fallback default and — after a fix applied during this audit — nowhere else; `Analytics.spec.ts` and `InterfaceContract.spec.ts` were corrected to derive the host/URL from `config.baseUrl` instead of a literal string.
- [x] Every test title carries `@styleup` and `@regression`, plus `@smoke`/`@demo` where applicable — grep for every `test(` title lacking `@styleup` or lacking `@regression` across `tests/` returns zero matches.
- [x] Every mapped Phase 1 step is wrapped in a `test.step()` — done throughout; the small number of single-action test cases (e.g. a single `expect()` with no distinct "step" in the register's own Steps column) call the page-object action inline without a redundant single-step wrapper, consistent with there being nothing else to name.
- [x] All test cases from one Section are in one spec file under `tests/<feature>/` — 36 spec files, each named after its Section, each containing every TC ID the register lists for that Section (cross-checked against `FILE_MANIFEST.md`).
- [x] Test data is referenced from `test-data/testData.ts`, not inlined — `searchTerms`, `defaultResultSet`, `boundaryProducts`, `existingAccount`, `outOfRangeCartEntry` cover the vast majority of seeded data; a handful of boundary tests spread a `testData.ts` base object with one overridden field inline (e.g. a specific 4-digit price for a Localisation check) — the base fixture and its shape still come from `testData.ts`, only the single varying value differs per case.
- [x] Wait logic uses `utils/waitHelpers.ts`, not raw `waitForTimeout` — grep for `waitForTimeout` across all `.ts` files returns zero real usages (one comment explicitly documents its absence).
- [x] Both Playwright HTML and Monocart reporters remain configured — `playwright.config.ts`'s `reporter` array; live-confirmed this session (`monocart-report/index.html` and `playwright-report/index.html` both generated by a real run).
- [x] `.env.example` updated for every new variable introduced — `BASE_URL`, `APP_USERNAME`, `APP_PASSWORD`, `TIMEOUT` are the only variables this project reads (via `utils/config.ts`), and all four are present in both `.env` and `.env.example`.
